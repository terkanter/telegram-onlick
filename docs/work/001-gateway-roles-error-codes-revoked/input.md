# Telegram fork — права, кадры отказов, код 4403: ТЗ для форка

Дополнение к [`telegram-fork-spec.md`](./telegram-fork-spec.md) (тот же конверт
`source: 'fanbeast-tg'`, те же правила origin). Контекст бэка — дроп 12.08
(фильтр слов и роли), платформенная половина уже в проде платформы (work cycle
003). Три независимых блока — можно сдавать по отдельности.

## 1. Вырезание функций по флагам прав

Платформа теперь кладёт в settings-пуш (тот же канал, что `blurImages`,
приходит за каждым `auth` и живьём при смене прав) блок `permissions`:

```ts
{
  source: 'fanbeast-tg',
  type: 'settings',
  blurImages: boolean,
  permissions?: {            // ← новый блок
    search: boolean,         // право telegram_client.search
    viewUsernames: boolean,  // право telegram_client.view_usernames
    forwardMessages: boolean // право telegram_client.forward_messages
  }
}
```

| Флаг `false` | Что вырезать |
|---|---|
| `search` | поисковую строку клиента |
| `viewUsernames` | никнеймы **во всех местах показа — их семь** (шапка чата, профиль, список контактов, форварды, реплаи, упоминания, ссылки-превью — сверить по коду форка) |
| `forwardMessages` | пункт «переслать» в меню сообщения (все три пути: обычная пересылка, без автора, «в Избранное») |

Правила:

- **`permissions` отсутствует в сообщении → показывать всё (fail-open).** Так
  ведут себя старая платформа и момент до загрузки прав; критичная пересылка
  всё равно отбивается сервером (`TELEGRAM_FORWARDING_NOT_ALLOWED`), так что
  рассинхрон не даёт утечки.
- Каждый следующий settings-пуш **заменяет** предыдущее состояние (в т.ч.
  появление/пропажа самого блока). Смена прав на лету приходит без
  переподключения — применять к уже отрисованному UI, как `blurImages`.
- Скрытие пересылки — UI-жест: сервер закрывает все три пути сам, кнопку
  можно прятать без оглядки на гонки.

## 2. Кадр ошибки шлюза: `errorCode`

Кадр ошибки получил необязательное машинное поле рядом с человеческим текстом:

```json
{ "type": "error", "id": 17, "message": "…", "errorCode": "TELEGRAM_MESSAGE_BLOCKED" }
```

| `errorCode` | Когда | Показ |
|---|---|---|
| `TELEGRAM_MESSAGE_BLOCKED` | в сообщении запрещённое слово | «Сообщение содержит запрещённое слово» |
| `TELEGRAM_FORWARDING_NOT_ALLOWED` | пересылка закрыта правом | «Пересылка сообщений вам недоступна» |
| `TELEGRAM_COMMAND_FORBIDDEN` | действие запрещено | «Это действие недоступно» |
| `TELEGRAM_SESSION_DEAD` | сессия анкеты умерла | «Аккаунт отключился, обратитесь к администратору» |

- Ветвиться по `errorCode`; показывать `message`. **Незнакомый код (или его
  отсутствие) → общий текст** — коды будут добавляться.
- **Не называть сработавшее слово** — текст отказа намеренно его не содержит
  (иначе список вычитывается перебором); ничего не дописывать от себя.
- Смерть сессии теперь отвечает всегда (раньше запрос висел вечно) — кадр с
  `TELEGRAM_SESSION_DEAD` должен снимать спиннер отправки.

## 3. Код закрытия соединения `4403`

Коды закрытия WS разведены (раньше всё приходило как 4401):

| Код | Что случилось | Что делать |
|---|---|---|
| `4401` | пропуск протух / сессия умерла / вкладка молчала | как сейчас: новый пропуск, переподключение |
| `4403` | **доступ отозван** (сняли назначение, деактивировали, удалили анкету, сменили команду) | **не переподключаться** — показать существующий экран «доступ отозван» (он написан, сейчас его никто не зовёт) |
| `4408` | токен не пришёл вовремя | как сейчас |

Без ветки `4403` сотрудник с отозванным доступом смотрит в вечное
«подключаемся». Прежние оговорки в силе: попытка переподключения ровно одна,
таймаутов у запросов нет.

Смежное (платформа уже сделала, форку знать): при анкете не в сети платформа
теперь **не выдаёт пропуск** (бэк отвечает 409) и сама показывает «Account is
offline» вместо iframe — до форка такой auth просто не дойдёт.

## Чек-лист приёмки

- [ ] `permissions` из settings-пуша вырезает поиск / никнеймы (все 7 мест) / «переслать»; отсутствие блока = всё видно.
- [ ] Смена прав на лету применяется без переподключения.
- [ ] Кадры ошибок ветвятся по четырём кодам; незнакомый код → общий текст; спиннер отправки снимается на `TELEGRAM_SESSION_DEAD`.
- [ ] `4403` → экран «доступ отозван», без реконнекта; `4401`/`4408` — как раньше.
