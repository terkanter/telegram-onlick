# План — несколько анкет в разных вкладках

Постановка и контракт — [`input.md`](./input.md). Платформенная половина идёт параллельно в `fanbeast-platform`, ветка `feat/030-telegram-multiaccount-tabs`.

## Группа вкладок по анкете

- [x] `config.ts`: константа параметра `tgAccount`.
- [x] `util/multiaccount.ts`:
  - `GATEWAY_ACCOUNT` из адреса iframe или из имени воркера, только в режиме гейтвея, с проверкой формата;
  - имена `tt-establish_*`, `tt-global_*`, `tt-multitab_*` берут `gw_<анкета>` вместо номера слота.

  Без `tgAccount` всё работает как раньше.
- [x] `worker/connector.ts`: передать анкету в имя воркера. Воркер сам шлёт `localDbUpdate` в канал группы.

## Мост к платформе в каждой вкладке

- [x] `index.tsx`: ставить мост и слать `request-settings` при старте каждой вкладки, а не в `initApi` главной.
- [x] `telegramGateway.ts`: сообщение `request-settings`.

## Контракт v2

- [x] `request-auth` несёт `tgAccount` и `requestId`. Форк помнит, какой запрос ждёт.
- [x] Входящий `auth`:
  - с чужим `tgAccount` — отклонить;
  - с незнакомым `requestId` — проигнорировать;
  - без полей v2 — принять, как раньше.
- [x] `ready`, `route-change`, `auth-error`, `form-content` несут `tgAccount`.
- [x] Сохранённый `auth` проигрывается новому обработчику только один раз. Использованный токен не отдаётся повторно при новом получении роли главной.
- [x] С `tgAccount` каждый следующий `auth` — переподключение на месте. Анкета внутри iframe не меняется, поэтому перезагрузка на «смену анкеты» не нужна.

## Потеря и повторное получение роли главной

- [x] `GatewayTransport.close()`: тихо закрывает сокет, гасит таймеры и отклоняет ожидающие запросы, не запуская политику переподключения.
- [x] `TelegramClient.destroy()` закрывает транспорт гейтвея.
- [x] `client.ts destroy`: сбросить транспорт и `isGatewayPostConnectDone`, чтобы новое получение роли прошло пост-коннект заново.

## Переподключение с другой анкетой

- [x] `client.ts connectGateway`:
  - если после переподключения id аккаунта гейтвея другой — не продолжать на старом клиенте, а сообщить основному потоку;
  - если при первом подключении `tgAccount` не совпал с id из `ready` — записать ошибку в лог.
- [x] Новое обновление `updateGatewayAccountMismatch`. Основной поток перезагружает вкладку и не удаляет кеш прежней анкеты.

## Статус гейтвея во всех вкладках

- [x] Статус остановки хранится в глобальном состоянии, без кеша, и синхронизируется между вкладками группы. `App` и `GatewayPending` читают его оттуда.
